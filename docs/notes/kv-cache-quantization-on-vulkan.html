Do not enable KV cache quantization on the Vulkan backend

Setting --cache-type-k q8_0 --cache-type-v q8_0 on llama.cpp with the Vulkan backend does not fail. It silently destroys throughput: generation went from 40 tok/s to 4.4 tok/s on a 7B Q4_K_M model.

The dequantisation path is not implemented for Vulkan, so the KV cache is converted on the CPU per token. On a discrete GPU that is slower than just keeping the cache in f16.

Check with a one-line benchmark before committing to it. On CUDA the same flags are usually a straight win.
