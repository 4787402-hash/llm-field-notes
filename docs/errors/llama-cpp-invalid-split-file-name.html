llama.cpp: error loading model: invalid split file name

error loading model: invalid split file name

Where: llama.cpp / llama-server, any OS

What you see

You concatenated a multi-part GGUF (name-00001-of-00002.gguf + name-00002-of-00002.gguf) into a single file to keep things tidy. llama-server now refuses to load it.

Why it happens

A split GGUF stores split.count = N in its header. Concatenating the parts gives you the bytes of both files but the header still claims the model is split, so the loader goes looking for a second shard that is no longer there. The byte count is right; the metadata is lying.

Fix

  1. Do not concatenate. Delete the merged file and keep the original shards.
  2. Point -m at the first shard only: -m model-00001-of-00002.gguf.
  3. Keep every shard in the same directory with its original filename. The loader resolves the rest from split.no / split.count.

Verification

Reproduced with Qwen2.5-7B-Instruct Q4_K_M split into two files (3,993,201,344 + 689,872,288 = 4,683,073,632 bytes). The merged file fails; pointing -m at shard 1 loads normally and reports the full parameter count.
