LiteLLM: request exceeds the available context size

litellm.ContextWindowExceededError: This model's maximum context length is 8192 tokens. However, your messages resulted in 20926 tokens

Where: LiteLLM proxy in front of llama-server / LM Studio

What you see

A coding agent works fine on hosted APIs but dies immediately against your local stack with a context-length error, even though the model supports far more.

Why it happens

The agent's system prompt alone is large. Claude Code ships roughly 21K tokens of tools and instructions before your first message. llama-server defaults to a small -c value, so the request is rejected at the proxy layer before the model sees it.

Fix

  1. Start llama-server with a context that covers the prompt: -c 32768 or higher.
  2. Budget VRAM for it. KV cache grows linearly with -c; on a 12 GB card a 7B Q4_K_M model at 32K context fits comfortably, at 128K it does not.
  3. If VRAM is tight, reduce the agent's context rather than the server's: the failure is about total prompt size, not output length.

Verification

Measured on an RX 6700 XT 12 GB with Qwen2.5-Coder-7B Q4_K_M. -c 8192 fails at 20926 tokens; -c 32768 completes. Time to first token at 21K prompt on this GPU: about 383 s, because prefill degrades as the prompt grows.
