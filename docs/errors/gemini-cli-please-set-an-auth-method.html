Gemini CLI: Please set an Auth method in your settings.json

Please set an Auth method in your /path/to/.gemini/settings.json

Where: gemini-cli 0.69+, ~/.gemini/settings.json

What you see

You already set the auth type, and the CLI still refuses to start and asks for an auth method. The key you wrote is silently ignored.

Why it happens

The setting is nested: security.auth.selectedType. A top-level "selectedAuthType" is accepted by the parser and discarded by the code. Separately, choosing the browser flow rewrites the value to oauth-personal, which is why it flips back after one successful login.

Fix

  1. Write the nested form: {"security":{"auth":{"selectedType":"gemini-api-key"}}}.
  2. Export GEMINI_API_KEY in the same shell you launch from.
  3. If it keeps reverting to oauth-personal, stop using the interactive login once; the file is being rewritten on exit.
  4. For a proxy endpoint, set GOOGLE_GEMINI_BASE_URL and keep selectedType at gemini-api-key.

Verification

Reproduced on gemini-cli 0.69.0. With the flat key the CLI printed "Please set an Auth method". With the nested key it read the API key and returned a completion against a local LiteLLM endpoint.
