OpenClash: Quick Start Mode skips config generation and the API port never opens

Step 3: Quick Start Mode, Skip Modify The Config File...

Where: OpenClash + mihomo on OpenWrt, aarch64

What you see

You delete the generated runtime config to force a clean rebuild, restart, and mihomo comes up on 127.0.0.1:7890 but port 9090 (external-controller) refuses connections. The runtime config file is 16 bytes.

Why it happens

OpenClash decides between a full rebuild and a shortcut in check_run_quick(). It sets quick_start=true and returns early when both /tmp/openclash.change and /tmp/openclash_config.tmp exist and /etc/config/openclash still matches the copy in that tmp file. Only when one of those markers is missing does it fall through to quick_start=false and actually run Step 3. Deleting the runtime config alone changes nothing, because the markers still say "nothing changed". The 16-byte file is the whole shortcut output.

Fix

  1. Delete the two markers, not just the config: rm -f /tmp/openclash.change /tmp/openclash_config.tmp /etc/openclash/free.yaml
  2. Restart: /etc/init.d/openclash restart
  3. Poll for the regenerate instead of sleeping a fixed time, because it takes 6-45 s depending on how many GeoSite records load: while [ $(wc -c < /etc/openclash/free.yaml) -lt 2500 ]; do sleep 1; done
  4. Confirm the log line you want is Step 3: Modify The Config File.... If you still see Quick Start Mode, the markers came back - delete them again in the same shell command as the restart.
  5. Do not use touch /etc/config/openclash or uci set openclash.config.restart=1 as the fix. Both were tried and both left the runtime config at 16 bytes, because uci commit rewrites the tmp copy that the comparison uses.

Verification

Reproduced on LibWrt (OpenWrt SNAPSHOT, aarch64, mihomo alpha-gbc76c13) with OpenClash 0.47. Full pool: deleting the markers produced a 579,970-byte runtime config in 41 s and both 7890 and 9090 listened. Trimmed pool (25 nodes, url-test group): 6,679 bytes in 6 s. Without deleting the markers the same commands produced a 16-byte file every time, and the router had no outbound connectivity until the markers were removed.
