PyYAML: 'gbk' codec can't decode byte 0x94

UnicodeDecodeError: 'gbk' codec can't decode byte 0x94 in position 18: illegal multibyte sequence

Where: Python + PyYAML on a Chinese-locale Windows install

What you see

A YAML config that loads fine on macOS or Linux throws a GBK decode error on Windows. The file looks like plain text.

Why it happens

On a zh-CN system Python opens files with the ANSI code page (cp936 / GBK) unless told otherwise. A UTF-8 file containing non-ASCII characters - a Chinese comment, a curly quote, an emoji - is not valid GBK, so decoding fails at the first such byte.

Fix

  1. Keep machine-read config files pure ASCII. Comments included.
  2. If you control the loading code, pass encoding="utf-8" explicitly.
  3. Do not "fix" it by saving as GBK - the next tool that reads it as UTF-8 will break instead.

Verification

Reproduced with a LiteLLM config.yaml containing a Chinese comment. Byte 0x94 at position 18 is the third byte of the first Chinese character. ASCII-only file loads.
